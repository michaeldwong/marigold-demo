You are working on the Marigold prototype: a dashboard for helping U.S. battery manufacturers understand and substantiate potential IRC Section 45X Advanced Manufacturing Production Credits.

Your task is to substantially simplify the existing dashboard and populate it using the NEW synthetic Volterra Battery Systems dataset that already exists in this repository.

This is a CUSTOMER DEMO, not a production system.

The primary goal is to demonstrate what Marigold could eventually do once an automated LLM/document-ingestion pipeline exists.

There is currently no live LLM pipeline. For this demo, YOU should analyze the provided customer-facing synthetic files ahead of time and populate the dashboard with the resulting structured analysis.

The experience should simulate:

customer files
    ↓
future Marigold extraction / normalization / analysis
    ↓
structured facts + evidence
    ↓
45X rules
    ↓
simple customer-facing insights

==================================================
3. PRODUCT PHILOSOPHY
==================================================

The current dashboard is too complicated.

This demo will be shown to people who may know VERY LITTLE about Section 45X.

The interface should therefore answer four questions extremely clearly:

1. DOES VOLTERRA QUALIFY?
2. HOW MUCH 45X CREDIT DO WE ESTIMATE?
3. WHERE DOES THAT CREDIT COME FROM / HOW WAS IT CALCULATED?
4. WHAT INFORMATION OR EVIDENCE IS MISSING?

Everything in the product should support one of those four questions.

If an existing element does not materially help answer one of those questions, strongly consider removing it.

We want:

- clean
- simple
- calm
- trustworthy
- explainable
- evidence-backed
- easy for a non-tax-expert to understand

We do NOT want:

- dense enterprise dashboards
- excessive tags
- dozens of metrics
- unnecessary graphs
- unnecessary tables
- walls of text
- unexplained tax terminology
- fake precision
- visual noise

Prefer progressive disclosure:
show the important conclusion first and let users drill down for details.

==================================================

8. ELIGIBILITY PAGE
==================================================

The Eligibility page should answer:

"Why does Marigold think we qualify or not qualify?"

Start with a prominent banner.

Examples:

✓ Volterra appears eligible for the Section 45X battery-cell credit

or

⚠ Volterra's eligibility cannot yet be fully established

or

✕ Volterra does not currently satisfy [requirement]

Use a large checkmark / warning / X and simple language.

Below that, enumerate the MAIN eligibility requirements.

Do not display dozens of obscure rules.

Show only requirements that materially affect this Volterra claim.

For each important requirement, display:

✓ satisfied
✕ not satisfied
⚠ unresolved / requires review

Examples of the kinds of things that may matter, depending on the actual repository rules:

✓ Eligible battery-cell product
✓ Produced by claimant
✓ Produced at U.S. facility
✓ Applicable technical requirements
✓ Qualifying sales
⚠ Supplier/material requirement unresolved

DO NOT assume these exact rules. Derive the actual set from the repository's 45X documents.

For each requirement:

- explain it in 1–2 plain-English sentences
- show the relevant Volterra fact
- link/reference the exact customer file(s) supporting the fact
- reference the exact 45X source document/rule supporting the requirement

If something is unresolved:

show exactly what additional action/evidence is needed.

Example:

⚠ VX-2170 Rev C qualification evidence

Existing qualification testing covers Rev B.
Rev C became effective July 1, 2026.
No evidence establishing whether the prior qualification remains applicable was provided.

NEXT STEP:
Obtain/review qualification evidence applicable to Rev C.

Do NOT have the software make legal/engineering judgments where the supplied evidence is insufficient.
